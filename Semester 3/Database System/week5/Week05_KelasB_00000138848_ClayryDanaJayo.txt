==== NOMOR 1 ====
-- 1a. Membuat database
CREATE DATABASE company;
USE company;

-- 1b. Membuat tabel-tabel

CREATE TABLE location (
    location_id VARCHAR(5) PRIMARY KEY,
    address VARCHAR(100),
    postal_code VARCHAR(10),
    city VARCHAR(50)
);

CREATE TABLE job (
    job_id VARCHAR(5) PRIMARY KEY,
    job_title VARCHAR(50),
    min_salary INT,
    max_salary INT
);

CREATE TABLE department (
    department_id VARCHAR(5) PRIMARY KEY,
    department_name VARCHAR(50),
    manager_id VARCHAR(5),
    location_id VARCHAR(5),
    FOREIGN KEY (location_id) REFERENCES location(location_id)
);

CREATE TABLE employee (
    employee_id VARCHAR(5) PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    birth_date DATE,
    email VARCHAR(100),
    phone_number VARCHAR(20),
    hire_date DATE,
    salary INT,
    job_id VARCHAR(5),
    department_id VARCHAR(5),
    FOREIGN KEY (job_id) REFERENCES job(job_id),
    FOREIGN KEY (department_id) REFERENCES department(department_id)
);

==== NOMOR 5 ====

Jika department.manager_id dijadikan FK ke employee.employee_id, maka akan
terjadi circular (mutual) foreign key dependency antara tabel employee dan
department:

- employee.department_id  -> FK ke department.department_id
- department.manager_id   -> FK ke employee.employee_id

Akibatnya:
1. CREATE TABLE: tidak ada urutan pembuatan tabel yang valid, karena masing-masing
   tabel butuh tabel lainnya sudah ada lebih dulu (masalah "telur dan ayam").
2. INSERT: baris pertama di kedua tabel tidak bisa diisi jika kedua FK wajib
   diisi (NOT NULL), karena manager/department yang direferensikan belum ada.
3. DELETE: menghapus seorang manager berisiko melanggar FK di department, dan
   menghapus sebuah department berisiko melanggar FK di employee yang masih
   menunjuk ke situ.

Solusi yang umum dipakai:
- Buat kolom FK-nya nullable, isi data secara bertahap (insert employee tanpa
  department dulu, baru insert department, baru update employee), ATAU
- Buat tabel tanpa FK constraint dulu, lalu tambahkan constraint-nya belakangan
  dengan ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY, setelah data awal
  kedua tabel sudah terisi, ATAU
- Nonaktifkan sementara FOREIGN_KEY_CHECKS (khusus MySQL) selama proses
  pembuatan tabel dan insert data awal.
